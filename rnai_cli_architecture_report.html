1 1. ภาพรวมโปรเจกต์ (Project Overview)

Rnai-CLI เป็นระบบ AI Agent CLI และ Web Interface ประสิทธิภาพสูง พัฒนาขึ้นเพื่อเป็นส่วนสำคัญในระบบนิเวศ Rnai.io โดยจัดอยู่ใน Phase 1 ตามแผนการพัฒนา 3 ระยะ (Rnai-CLI → Worker Daemon → Cowork WebApp)


🤖 Multi-Model Chat & Compare

สนทนากับ rnai-llm บน Modal/Rnai.io API และเปรียบเทียบคำตอบและ Latency ร่วมกับ Groq, Gemini, OpenRouter, Cerebras, Mistral, GitHub Models, Ollama

🧠 Hybrid Agent System

ระบบผสมผสานระหว่าง Planner Brain (Groq/Gemini สำหรับวางแผน tool-calling) และ Voice Refinement (rnai-llm ปรับบุคลิกภาษาไทย)

🛠 Background Worker & Web UI

คิวงานเบื้องหลังด้วย macOS launchd daemon และ Web UI ในตัวแบบ Zero-Dependency รองรับ PWA บนมือถือและเดสก์ท็อป

4 4. การวิเคราะห์ระบบหลักเชิงลึก (Core Component Analysis)

โมดูล หน้าที่หลัก การออกแบบสถาปัตยกรรม (Design Patterns)
main.py / config.py CLI Command Controller & Settings Manager ใช้ Typer Command Pattern + Rich Console Render, เก็บ config ที่ ~/.rnai/config.json โดยบันทึกเฉพาะค่าที่ต่างจาก default เพื่อความปลอดภัย
auth.py Authentication & Rnai.io Platform API ทำ Firebase signInWithPassword นำ Token ไปขอ Mint permanent API Key (rnai_sk_...) และจัดการ platform_chat() กับ Server-side quota fallback
providers.py Universal LLM Provider Wrapper OpenAI-Compatible Abstraction Layer, มี Exponential Retry สกัดเวลาจาก Retry-After header และใช้ Regex Tag Parser แกะ Tool Calls ที่หลุดฟอร์แมต
agent.py & tools.py Hybrid Agent & Tool System Planner-Voice Architecture: Groq/Gemini ทำ Function Calling multi-steps + สลับ Fallback ชั่วคราวเมื่อ Groq ล้มเหลว, มี Human-in-the-loop approval
research_tools.py Research Profile & Scaffolding Fading มี _guard() บังคับ Fading Level (L1, L2, L3) ในระดับโค้ด ป้องกัน AI Hallucination และบันทึก JSONL Log สำหรับใช้เป็นหลักฐานงานวิจัย
worker.py Background Daemon & Task Queue รองรับการตั้งเวลา (daily, every N min, once) มีระบบสกัดเป็น macOS launchd plist และแจ้งเตือนผ่าน OS Notification
ui.py Single-File Web App & PWA Server ใช้ ThreadingHTTPServer (Stdlib) ไร้ภาระ Node/NPM มี REST API Endpoint ในตัว พร้อมฝัง Manifest + Service Worker ให้ติดตั้งเป็น PWA ได้
💡 ไฮไลท์สถาปัตยกรรมสำคัญ: Hybrid Planner + Voice Paradigm
ระบบแยกส่วนการ "วางแผนและคิด" (Planner) ออกจาก "การเรียบเรียงน้ำเสียง" (Voice) อย่างชัดเจน:
  • Planner: ใช้โมเดลที่เก่งด้าน Tool-Calling และ Logic (เช่น Llama-3.3-70B บน Groq หรือ Gemini-2.5-Flash) เพื่อทำงานให้เสร็จเร็วที่สุด
  • Voice: ใช้โมเดล rnai-llm เรียบเรียงผลลัพธ์ดั้งเดิมจาก Planner ให้กลายเป็นภาษาไทยที่เป็นธรรมชาติ สไตล์ Rnai โดยไม่ดัดแปลงตัวเลข ข้อเท็จจริง หรือลิงก์

5 5. จุดเด่นและข้อเสนอแนะในการพัฒนา (Strengths & Recommendations)

✨ จุดเด่นทางสถาปัตยกรรม (Key Strengths)
  • Zero-Heavy Dependencies: ใช้เพียง typer, rich, httpx ติดตั้งง่าย รวดเร็ว และไม่มีปัญหาความขัดแย้งของไลบรารี
  • High Fault Tolerance: มี Retry ลูปสำหรับ HTTP 429, มี Fallback Planner ข้ามค่าย (Groq → Gemini) และมี Regex สกัด Tool Call Recovery
  • Layered Security: กิจกรรมที่แก้ไขระบบ ต้องได้รับการยืนยันจากผู้ใช้ก่อนเสมอ และโหมด Worker เบื้องหลังจะปิด Shell Command โดยอัตโนมัติ
  • Portable Web UI / PWA: รัน WebApp ได้ทันทีโดยไม่ต้องลง Node.js หรือสร้าง Build Pipeline
🚀 ข้อเสนอแนะพัฒนาต่อ (Next Steps)
  • UI Code Modularization: แยก HTML/CSS/JS จาก ui.py ออกเป็นไฟล์ static template เพื่อการบำรุงรักษาที่ง่ายขึ้น
  • Server-Sent Events (SSE) Streaming: เพิ่มระบบ Streaming Response ใน Web UI สำหรับขั้นตอนการคิดของ Agent ให้เห็นภาพแบบ Real-time
  • Linux / Windows Daemon Support: ขยายระบบตั้งเวลาจาก macOS launchd ให้รองรับ systemd service สำหรับนำไปรันบน Linux Cloud Server
